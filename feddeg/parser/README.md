# Сбор и обработка данных федерального ДЭГ

Код превращает JSONL-дамп блокчейна и метаданные портала в стандартные CSV-таблицы. Обработанные данные старых лет лежат в `data/feddeg-data`, ссылки на исходные криптографические данные в README.

Из-за роста объема данных в 2026-м году подход стал потоковым. Запишите `dump-chunked.py` на флешку, вставьте её в подготовленный ноутбук в помещении ОП Рф, примонтируйте и выполните в консоли в директории флешки `python dump-chunked.py`. Скрипт начнет писать файл в эту же директорию и сам возобновит работу при остановке. Чтобы перенести на другой компьютер, нажмите ctrl+c чтобы его остановить и размонтируйте флешку. После чего запустите `parse.py` чтобы нарезать готовые таблицы.

Важно: пока `dump-chunked.py` не запущен, новые блоки не выгружаются вообще. Дыра получается по времени (пропадает хвост), а не внутри цепочек: при следующем запуске скрипт продолжит с последнего целого чанка. Ещё он каждый проход запоминает высоту цепочек из ответа узла в самом начале прохода, поэтому сразу после прохода дамп всегда отстаёт от текущего конца на длительность прохода.

Скрипт можно заменить на новую версию прямо во время выгрузки: остановите его ctrl+c (он встаёт между чанками, состояние уже записано), положите новый файл на место старого и запустите ту же команду. Он продолжит с `completed_through` из `state.json`, ничего не перекачивая: уже готовые диапазоны проверяются на целостность и не запрашиваются заново. Формат файлов при этом не меняется — каталог сохраняет тот суффикс, с которым его вела прошлая версия (`.jsonl.gz` так и остаётся сжатым, `.jsonl` — сырым), а новый каталог пишется в gzip, как и в предыдущей итерации; явные варианты — `--compression gzip|none`.

Черновик параллельной версии (2026-09-18):

- цепочки качаются каждая в своём потоке (`--shard-workers`, по умолчанию — все), внутри цепочки работает окно опережающей загрузки `--fetch-depth`, поэтому gzip считается внахлёст с сетью;
- число одновременных запросов подстраивается само по схеме AIMD: при 429/5xx и таймаутах лимит уменьшается вдвое и замораживается на `--cooldown`, дальше медленно растёт по мере успехов. Начальный/минимальный/максимальный лимит — `--initial-concurrency`, `--min-concurrency`, `--max-concurrency`;
- память ограничена `--max-inflight-chunks` (по умолчанию 8; один распакованный чанк на 100 блоков — это ~130 МБ объектов Python);
- узел, который не ответил на разведку, больше не «теряет» свою цепочку: каталог остаётся, имя берётся из `state.json`, и такой проход просто неудачно попробует догрузить хвост, не роняя остальные цепочки;
- имена каталогов теперь стабильны: известная цепочка всегда сохраняет своё имя, а новая получает имя по номеру слота из инвентаря узлов (`i…nodeobs05` -> `shard-0`, `…obs65` -> `shard-6`), суффикс `-fork-N` остаётся только для настоящих расхождений.

`check-observers.py` рядом: опрашивает все узлы, показывает, какую цепочку отдаёт каждый и сколько блоков не хватает, и печатает урезанный список `OBSERVER_NODES` (по одному узлу на цепочку, чтобы качать только недостающее).

Одной командой можно собрать сразу всё: таблицы, ZIP-архив с ними и график явки по годам. `--dump` принимает не только файл (или `/dev/stdin`), но и директорию `block-dump` целиком: цепочки читаются по очереди, границы восстанавливаются по высотам блоков. Копировать дамп никуда не нужно.

```bash
python3 parse.py \
  --dump /media/sereja/Terabyte/deg/block-dump \
  --out /tmp/feddeg-run/tables \
  --cache /tmp/feddeg-portal-cache \
  --archive ../../data/feddeg-data \
  --turnout-comparison turnout_comparison_2024_2025_2026.png \
  --reference 2024=../../data/feddeg-data/edg2024.zip \
  --reference 2025=../../data/feddeg-data/edg2025.zip \
  --turnout-current-label '2026 (частичные данные)' \
  --mark-elapsed '11.54=11:33 МСК — выгрузка трёх цепочек из четырёх прервана'
```

- `--out` — куда писать таблицы; рядом появится `per_contract.csv` с диагностикой «дамп против портала», в архив он не попадает. Пять публикуемых таблиц: `elections.csv`, `results.csv`, `ballots.csv`, `votes.csv`, `voter_list_events.csv` (событийный лог списков избирателей, пришёл на смену `uiks.csv` в 2026-м — почему, написано в `data/feddeg-data/README.md`).
- `--cache` — кэш ответов API портала. Повторные прогоны с той же директорией бесплатны (около 6400 попаданий), с новой — это 6 тысяч запросов к порталу.
- `--archive` — директория (тогда имя `feddeg_<московское время>.zip`, а если такое уже есть, добавится `_1`, `_2`) либо конкретный путь к файлу. Существующие архивы не перезаписываются.
- `--turnout-comparison` — график «явка по годам»: по панели на набор данных, часы считаются от первого бюллетеня. Панель текущего дампа всегда последняя и красится в свой цвет, прошлые годы задаются через `--reference ЛЕЙБЛ=ZIP` (подойдёт и распакованная директория с `ballots.csv`).
- `--mark-elapsed ЧАСЫ=ПОДПИСЬ` — вертикальная пунктирная отметка на панели текущего года. Обрыв выгрузки не должен читаться как падение явки, поэтому такие места стоит помечать руками.

Про `coverage` в конце вывода: счетчики портала (`issued`, `voted`) считают ещё и перевыдачи и суммируются по всем голосованиям, так что для оценки полноты дампа они не годятся. Сравнивать нужно самих избирателей (тип `initial` в `voter_list_events.csv`) и бюллетени.

Проект экспериментальный, что-то из этого может не работать.

Старый пайплайн находится в `dump-legacy.py` (`python dump-legacy.py > dump.json`) и `parse-legacy.ipynb`.
